# mini_agent 全量双后端生成实验

用户要求把全部 mini_agent 评测集交给 Direct/DeepEval 生成并比较，已授权真实API调用、当前会话直接实施。范围为 full_tools_fixture_v1 的847个覆盖槽位、23个目标；不包含独立 nanobot，也不累计历史query_user重复轮次。

采用完整配对的一轮：每个槽位两个后端都生成，按槽位交替先后顺序，8个并发配对任务，每个任务内部顺序执行两个后端，每后端每槽位最多3次尝试。无需再让用户选择执行方式。相比只抽样，这能覆盖全量；相比四组全量重复，本轮先检验跨能力泛化，不声称统计显著性。

两边共享来源、计划、JSON候选协议、契约验收、模型和所有采样参数。沿用deepseek-flash、temperature0.4、thinking关闭、max_tokens4096、无HTTP自动重试。DeepEval4.3.2保持多阶段、禁用演化/质量阈值0，防止抹掉故意异常输入。生成期间不调整规则/提示词；每次请求、原始输出、反馈、usage和耗时落盘，可恢复完成槽位，不重复已完成API调用。

365行为槽位、202静态检查和280原始阻塞项必须分别报告，不混为行为覆盖。阻塞项由模型生成缺口说明/建议补充的信息，严格禁止Oracle；不强行生成没有依据的可执行刺激。旧生成结果只用于读取格式/状态/定义类别等计划元数据，不提供旧输入或旧预期给模型。重新审查发现的契约缺口必须额外标记，例如缺参枚举不是精确映射：意图missing/invalid全量Oracle有缺口时降为input-only，不照抄旧生成器硬编码答案。

新候选协议：input结构化对象、preconditions数组、oracle对象或null、evidence_refs、rationale；只有已知缺口使用gap说明。模型独立生成刺激与期望，框架装配稳定ID和来源。参数案例验证声明参数的有效/非法类型/遗漏/边界以及其余参数合法；静态检查期望必须与源JSON Pointer值相同；工具结果/事件/规则/链路根据快照检查关键可观测断言；模块意图检查参数、状态动作、值与输入一致。语义检查有边界，不能把格式通过写成运行成功。输出保存独立Candidate和可装配定义，保留runner限制及PENDING审核状态。

重复统计在两边生成结束后按确定性顺序做，不影响并发次序和重试预算。保留影响语义的@、负号、标点和JSON类型；不同槽位复用同一刺激单独报告，不将静态检查或不同断言直接当作重复行为错误。这是新版本全量实验策略，不改动上次42槽位实验或其规则。

分层报告：所有槽位是否尝试、首试/最终程序验收、失败类别、已知阻塞合规率、额外Oracle缺口、结构化重复、按目标和层级覆盖、API次数/token/cache/服务耗时/实验墙钟时间/费用估算。并发下请求累计延迟与单组串行时间不可混称。独立AI语义审查覆盖全量行为候选，静态检查由程序逐条比对来源；阻塞说明检查未编造预期。AI初审不等于人工批准。

历史suites/workspaces内容与当前快照哈希锁定；新实验使用独立工作区，产物与密钥隔离，结束验证历史/来源/请求参数一致性。无提交、推送、Agent真实执行、人工审核冒充或冻结。
