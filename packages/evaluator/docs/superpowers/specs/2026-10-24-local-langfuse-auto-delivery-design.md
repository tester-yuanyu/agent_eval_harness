# 本地 Langfuse 与评测自动交付方案

状态：用户于 2026-10-24 回复“执行”，已批准本方案，实施和本机验收已完成。

## 用户目标

Langfuse 运行在用户自己的电脑上。每次评测结束，自动生成报告、更新本轮看板并返回链接。此前使用 Cloud 是现有部署选择，并非 Langfuse 或 Evaluator 的技术要求。本次请求不授权继续向 Cloud 上传评测数据。

## 当前事实

- 普通 run 和候选 ZIP 的分区 run 都已经自动调用 `write_report`，保存本地正式结果与 Markdown 报告。
- 看板导出仍是独立的 `export-langfuse` 操作，没有接到每次运行结束后的交付流程。
- 当前电脑为 Apple Silicon；PATH 和标准应用位置未发现 Docker、Podman、Colima 或 OrbStack。
- 已有 Langfuse SDK、导出检查点和原生看板 API 可复用。历史 Cloud 配置和结果需要保留可读性。

## 方案选择

推荐使用官方 Docker Compose 在本机运行 Langfuse，默认通过 `http://127.0.0.1:3000` 访问；实际端口先检查占用。本地持久卷保存数据库与对象存储，容器仅重启时保留历史数据。建议使用 Docker Desktop 提供 macOS 容器环境；这是实施选择，尚未安装。

继续使用 Cloud 需要对外传输，与本次本地需求不符。仅使用 Inspect View 可立即查看执行记录，但无法提供用户指定的完整 Langfuse 实验、看板及复核体验，因此保留为辅助查看入口。

## 自动流程

1. Inspect 完成执行与正式判分。
2. Evaluator 保存不可变 `results.json`、汇总、已有门禁结果及报告；候选包同时保存接入和阻塞账本。
3. 交付模块读取这些权威产物，向显式配置的本地 Langfuse 同步状态、已有分数和必要元数据，并更新原生看板。默认沿用不包含业务输入输出的内容模式。
4. 每个运行或候选交付生成可追溯的交付回执，包含报告路径、本轮看板和实验链接、同步状态及来源 Hash。CLI 和报告都返回可点击入口。
5. 将 Nanobot v3 的现存两个运行补入本地展示，无需重新调用 Agent。

## 展示与失败处理

- 静态检查和行为评测分开展示；未执行数量、阻塞类别、临时结果及门禁结论读取已有账本与结果。
- 不把未执行项当作 Agent 失败，不从展示数据重新计算另一套正式通过率；无正式通过率时显示不适用。
- 部分完成、运行失败、准入失败也生成本地交付说明；没有 Trial 的记录不伪造 Trial 或评分。
- Langfuse 不可用时，评测结果与退出码语义保持原样，回执标记展示待同步；下一次运行的交付阶段或显式重试命令补同步，不能重跑 Agent 来补看板。
- 已确认接收的数据按既有检查点去重；接收状态不明确时先核对再续传，不能盲目重发。
- 本地目标使用独立配置和按目标区分的回执，不覆盖已绑定 Cloud 项目的历史导出记录；默认流程不回退到 Cloud。

## 实施边界

保留 Inspect／Evaluator／Langfuse 分工，不开发另一套看板前端或评分引擎。服务默认只监听本机；数据库和服务凭据随机生成、保存在受保护且被 Git 忽略的本地文件，不进入报告。关闭可关闭的产品遥测；安装时下载官方软件及镜像不等同于上传评测数据。

本地部署需要一次安装、初始化以及后续服务运行。容器版本与部署配置固定并记录来源。若 Docker 首次启动要求用户接受协议或系统授权，该系统步骤交由用户完成；其余评测和展示流程自动执行。

## 验收

- 本地 Langfuse 健康检查、UI 登录和原生看板可打开。
- 两类 CLI 运行路径都能输出报告和正确限定本轮数据的看板链接。
- Nanobot v3 展示 2,445 条静态检查、3 条行为测试、276 条未执行及临时/门禁状态，与既有结果一致。
- 测试服务不可用、部分完成、全阻塞、重复同步和历史 Cloud 回执共存；正式结果 Hash 与评分不变。
- 使用扩展自身 `pyproject.toml` 运行相关测试与 lint，再按改动范围完成回归。
