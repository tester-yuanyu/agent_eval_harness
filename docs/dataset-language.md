# 评测集语言说明与中文阅读入口

仓库文档以中文为主；冻结评测数据保留原始字节，并通过独立阅读文件补充中文说明。当前三套基准中，实际交给模型或 Agent 的任务指令已经是中文。英文主要出现在说明元数据、程序模块测试说明，以及需要精确保留的文件内容、参数和标识符中。

打开[中文逐条阅读页](dataset-reading.html)，可按数据集、执行类型或关键词查看全部 744 条任务记录。页面提供具体任务、后续指令、上下文、中文说明及冻结原文。它不调用模型、不执行工具、不重新评分，也不会被 Harness 作为任务输入加载。

## 当前基准的准确统计

本次审计以 2026-11-01 仓库中的冻结源文件为准。统计先按字段用途区分自然语言、代码和字面量，再检查汉字分布并核对任务模板；不是通过整个 JSON 是否出现英文字母来判定任务语言。

| 数据集 | 任务记录数 | 中文 `prompt` | 英文 `prompt` | 中文后续指令 | 中文 `decision_context` | 英文 `description` |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `file-tools-v1` | 300 | 300 | 0 | 40 | 0 | 300 |
| `file-tools-v2` | 420 | 360 | 60 | 75 | 0 | 420 |
| `model-decisions-v1` | 24 | 24 | 0 | 0 | 24 | 24 |
| **合计** | **744** | **684** | **60** | **115** | **24** | **744** |

这些是记录数，不是独立业务问题数：v2 继承 v1 的 300 个端到端实例，且每个任务族含有相关的参数变体。不能把跨版本的 744 条记录当作 744 个独立测试能力。

v2 的 60 条英文 `prompt` 全部属于 `execution_mode=module`。这条路径执行固定的 `module_calls`，调用真实程序工具，不调用 LLM。360 条 Agent 任务指令由 60 条关键链路和 300 条端到端任务组成。24 条独立模型决策使用中文任务及公开上下文，但不执行返回的工具调用。

另外，v2 有 60 条英文 `reference.description` 和 3 条英文 `errata`；独立决策集有 24 条英文 `reference.description`。这些说明已在阅读页与逐条对照中提供中文版本。三套 Manifest 的来源、切分与适用范围，以及质量报告的主要说明，在中文数据集说明及阅读页中解释；冻结 JSON 内的原文保持不变。

## 不同字段应怎样处理

| 内容类型 | 例子 | 是否进入执行或评分 | 处理方式 |
| --- | --- | --- | --- |
| 任务指令与公开上下文 | `prompt`、`followups`、`decision_context` | 模型／Agent 任务中会进入执行 | 当前中文原文保留；新增语言必须成为独立数据版本 |
| 程序模块说明 | 60 条固定模块测试的英文 `prompt` | 随模块输入传入，但不请求模型；实际调用由 `module_calls` 指定 | 在旁路文件中按具体工具与参数解释，不改变原任务 |
| 说明与勘误 | `description`、`reference.description`、`errata` | 不属于 `execution_task()` 交给 Agent 的字段 | 补中文对照，逐条记录来源 ID 与 Hash |
| 文件与参数的精确内容 | `source.txt`、`mode=debug`、`RESULT=2`、CSV 表头、JSON 键、换行 | 可能影响读取、工具参数或精确终态评分 | 保留原始字面量，不作为英文正文改写 |
| 契约标识符 | `read_file`、`expected_replacements`、任务 ID、枚举值 | 供程序解析、匹配和引用 | 保留英文标识符；在文档中解释含义 |
| 私有评分数据 | `oracle.expected_files`、检查点、预期参数与匹配消息 | 仅供可信评测侧使用 | 保留冻结内容；不得把中文解释或参考答案送入 Agent |
| 历史运行证据 | 工具返回、模型回复、错误消息、轨迹 | 属于已经发生的观测 | 保留原文；解释单独记录，不伪造新的模型输出 |

三套基准共包含 1,749 个初始文件内容字符串，含重复继承的数据；这些初始内容均不含汉字，其中 1,737 个包含拉丁字母，其余 12 个为数字、空白等内容。它们包含配置、CSV、JSON、路径和测试文本，不能简单全部归为“英文说明”。v2 的 15 个写文件模块实例要求写入含中文的文件内容，该精确输出同样保留。

因此，准确的语言描述是：**中文任务指令为主，操作包含英文标识符、结构化数据和精确文本的文件环境。**这不是纯中文长文本理解基准，也不能仅凭中文指令证明双语能力。

## 语言变化怎样影响成绩

中文对照不进入执行输入，因此不改变既有成绩，也不产生一份“中文版本已运行”的新证据。现有分数仍然只对应原数据 Hash、运行配置及评分版本。

如果实际修改 `prompt`、后续指令、上下文、工具 Schema 描述或文件内容，会改变模型看到的输入。即使只是翻译，也可能改变歧义、分词、工具选择和格式遵循；不能直接把翻译后的得分替换到旧基线。更改精确匹配的回复标记或预期文件内容，还会改变评分任务本身。

正式比较需要固定同一个数据版本、评分配置和运行条件，把模型、Agent 或语言中的目标变化显式列为实验变量。语言对照实验应使用有来源映射的成对任务，分别报告中文和原语言结果，并说明适用范围与样本规模。

## 需要真正的新语言版本时

新建独立目录，例如 `data/benchmarks/file-tools-v2-zh-CN-v1/`，这是未来版本的路径示意，当前没有因此创建或执行新基准。

1. 先明确翻译范围：只翻译用户指令，还是同时本地化工具描述、文件文本及预期答案。当前指令已是中文，不能仅修改英文元数据就宣称新增中文能力实验。
2. 新任务保留 `source_task_id` 或等价映射，并记录源数据 Hash、语言范围与翻译依据；新旧数据不能共用同一数据集身份。
3. 审核歧义、单位、空格、换行、字面标记及多轮约束，重新检查输入与预期的一致性；完成审阅后再冻结新的 Manifest 和 Hash。
4. 运行新的结构／参考验证，再显式执行真实模型评测，单独保存新的 Run ID、配置和成绩。参考验证通过不等于模型通过。
5. 官方 τ-bench 等外部数据继续使用官方任务身份和语言；翻译或改写后只能标为派生实验，不能把派生成绩冒充官方成绩。
