# Harness P1：nanobot 双接入与停止策略

**Goal:** 完成用户确认的 P1，保留成本边界及历史路径。
**Spec:** 用户本轮列出的 P1 三项；此前四层边界继续有效。
**Architecture:** `nanobot` / `NanobotRuntimeAdapter` 保留子进程原生 AgentLoop；新增 opt-in `nanobot_component` / `NanobotComponentAdapter`，使用 nanobot 原生 ContextBuilder 和工具参数解析组件，经 Inspect 模型接口运行在自研 loop 内。

## Global Constraints

- 不改变冻结任务、历史结果、DeepEval 评分；不调用付费模型或托管服务。
- 不修改外部 nanobot 源码。原生组件是可选依赖，按环境加载唯一版本，不按 sample 改 sys.path、全局配置、logger、tokenizer 或环境变量。
- 组件 profile 禁用个人 bootstrap、memory、skills、插件及原生工具执行；公开任务 policy/instructions 和环境工具 schema 有效。此 profile 与原生 runtime 是不同实验条件，不宣称分数等价。
- TimeoutStop 显式限制 loop 的 wall time（含模型和工具 await），Inspect 仍是外层兜底；ErrorStop 对连续可恢复工具错误计数，成功后清零，默认不新增错误预算，配置后启用。基础设施异常继续抛出。
- P2 动态用户模拟和全量 file-tools-v2 对比留待后续；保留旧路径。
