## 评分与历史结果

- 正式确定性指标以终态、模块实际输出、参数约束和声明检查点为依据；诊断分不能抵消正式失败。
- v2.1 复评写入新目录，保留原观察、原判定与来源 Hash。它不调用 Agent，不增加执行次数。
- Judge 重复评分针对同一保存证据，另计评价次数。它不增加任务实例数或 Agent trial 数。
- File Tools v2 继承的 v1 holdout 已用于历史运行；不能把它包装成从未见过的新验收集。模型决策 holdout 的任务族分布也不同于 dev，不代表均衡随机抽样。
- 旧 v1 的原始数据和 1,800 次结果保持不变。跨任务或评分版本差异不能直接解释为模型能力变化。

## 完成验收仍需要什么

1. 完成公开 HTML 的浏览器视觉验收及后续在线发布。当前 HTML / JSON / 链接通过静态检查，本地文件浏览受浏览器 URL 策略限制。Langfuse 六组服务端回读与模型决策界面抽查均已完成；尚未将作品集发布到公开网站或推送 GitHub。
2. 独立人工填写 [36 条校准样本](../../reports/file-tools-v2/calibration-sample.json)，再进行一致性、误放 / 误杀评估及另外留出样本的阈值验证。样本来源为 chain-judge，按稳定 Hash 抽取三个维度各 12 条，目前全部为空白标签。
3. 处理 GEval 的 1 项 ValidationError：实际返回 JSON 只有 reason，缺少 score 字段。原始输出已保存；不能从理由文字推测分数。后续可增加格式约束或有界重试，并保留原错误及新评审记录。
4. 在已完成的单任务 τ 试点上扩大 retail 任务范围与重复次数；包含自然语言断言的任务还需显式启用并验证官方 Judge。已有任务 0 的 reward 1.0 不能证明这些范围。
5. 逐步增加真实业务任务、动态用户场景及更广的模块覆盖，不能用合成参数变体替代泛化证据。

事后 Judge 关联到原 Trace 时，根 Span 的起止跨度包含执行结束至评审发生之间的间隔；实际 Agent latency 保留原执行时长，不能把这个跨度称为 Agent 耗时。

上述“待完成”会随新的可检查证据更新。执行命令见 [v2 使用指南](v2-usage.md)，公开报告使用 [作品集生成器](../../scripts/build_layered_report.py)。
