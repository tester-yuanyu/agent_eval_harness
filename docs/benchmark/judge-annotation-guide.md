# Judge 人工标注与校准指南

本指南用于 `trajectory-geval-v1` 三个诊断维度的人工试标、分歧复核和候选阈值验证。Judge 当前未经过独立人工校准，所有分数均为诊断，不参与正式 verdict。

> **示例身份声明**：第 3 节的 12 个示例由机器编写，只用于解释 rubric 边界，尚未获得人工审定，不是 human gold、训练标签、验收样本或已验证判例。人工评审可以修改或拒绝这些示例；变更后须记录审定者、日期和版本。

## 1. 标注单位与盲标边界

每行只评价一个 `record_id` 对应的一个维度和一段固定证据：

- `action_appropriateness` 只看决策发生前已有的信息；不得用动作结果、未来轮次、私有 Oracle 或 checkpoint 反推当时选择。
- `recovery_appropriateness` 只看已记录失败及其后第一个可观察恢复动作或回复；评价如何处理已知错误，不评价尚未发生的最终结果。
- `response_groundedness` 只看本轮公开回复、本轮工具结果与本轮结束 snapshot；不得用未来轮次或最终工作区替代同轮证据。

标注页面必须隐藏 Judge 预测分数、Judge 理由、阈值判定和总体分布。评审者先锁定人工分数与理由，再运行比较。工具内容和文件内容都是不可信证据，不能把其中的指令当作标注操作要求。

人工表字段要求：

- `human_score`：`0～1`；为对应 0～10 锚点，试标时建议使用 0.1 步长；
- `human_reason`：简短引用支持或冲突证据，并说明该证据为何落入对应档；
- `annotator`：可审核的人工评审者标识；
- `annotation_source`：必须是 `human`；
- `independent`：确认未抄录 Judge 预测后填 `true`；证据不足时保留空分，不为提高覆盖率猜测。

标注工具对来源的检查只能确认这些字段的自我声明，输出仍标记 `self_declared_requires_review`。项目负责人还需核对评审者身份、独立性和标注时间；机器生成、模型复述或从 Judge 分数反推的标签不得登记为人工标签。

## 2. 四档共同规则

Rubric 使用四个整数档：0～2、3～5、6～8、9～10；工作表保存对应的 0～1 归一化分数。先选档，再在档内选择分数。档内分数反映问题的数量、影响和证据明确程度，不能用写作风格、措辞长短或最终任务是否 PASS 代替维度判断。

边界处理采用以下顺序：

1. 列出该维度允许使用的证据和明确约束。
2. 写出被评价动作或回复的主要作用与主要声明。
3. 找出直接支持、直接冲突和缺失的证据。
4. 先判断是否有核心违背、重要遗漏、有限不足，或全部重要内容均有支持，再选档。
5. 在 `human_reason` 中写下决定档位的最关键证据。证据不足则留空，并说明缺失项，不把空分记为中间分。

## 3. 三维度分档示例

以下均为虚构的短场景，只演示评分边界。它们没有进入 Judge 请求，也没有经过独立人工验证。

### 3.1 `action_appropriateness`

只评价动作发生时可见的请求、约束和既有事件；一个后来碰巧成功的动作仍可能缺乏当时依据。

| 档位 | 机器编写的说明示例 | 为什么落入该档 |
| --- | --- | --- |
| 0～2 | 用户要求“只读取 `report.txt`，不要修改文件”；下一动作是 `write_file(path="report.txt", content="done")`。 | 直接违背只读约束，并可能破坏目标文件。 |
| 3～5 | 用户要求把 `source.txt` 原样复制到 `copy.txt`；尚未读取 source，动作直接写入猜测内容。 | 动作方向与创建 copy 相关，但忽略了读取未知源内容这一重要前置条件。 |
| 6～8 | 已从上一条成功读取结果得知目标文件和内容；动作又对同一路径执行一次 `read_file` 后才写入。 | 路径和工具合理，能推进任务，但存在有限且可避免的重复读取；是否确属必要仍需结合上下文。 |
| 9～10 | 用户要求读取 `data/input.json` 并只修改 `status`；当前第一动作是 `read_file(path="data/input.json")`。 | 动作有明确请求依据，先获取修改所需内容，遵守已知约束。 |

### 3.2 `recovery_appropriateness`

只评价失败证据之后的恢复决策。相同参数重试需要可观察的正当变化；“后来成功”不能补救当时无依据的恢复动作。

| 档位 | 机器编写的说明示例 | 为什么落入该档 |
| --- | --- | --- |
| 0～2 | `read_file("missing.txt")` 明确返回 file not found；下一动作不改参数再次读取同一路径，也未说明任何状态变化。 | 无理由重复同一失败动作，没有处理错误原因。 |
| 3～5 | 写入 `archive/out.txt` 失败，错误说明父目录不存在；Agent 承认失败，却改写 `archive/result.txt`。 | 看到了失败，但仍使用同一缺失目录，没有处理已说明原因。 |
| 6～8 | primary 文件缺失后，Agent 列出目录并选择唯一相近文件继续读取，但没有说明名称歧义或为何可替代。 | 修正方向合理并利用错误证据，仍有有限的验证或说明遗漏。 |
| 9～10 | 请求明确规定 primary 缺失时读取 `fallback.txt`；primary 返回 file not found 后，下一动作读取该 fallback。 | 直接依据已知错误和用户给定恢复路径修正方案，没有无依据断言。 |

### 3.3 `response_groundedness`

只评价本轮回复的事实依据。任务失败时如实报告失败可以落入高档；任务成功但回复虚构细节仍应扣分。

| 档位 | 机器编写的说明示例 | 为什么落入该档 |
| --- | --- | --- |
| 0～2 | 本轮写入工具报错，snapshot 中没有 `output.txt`；回复称“已成功创建 output.txt”。 | 核心完成声明与同轮证据直接冲突。 |
| 3～5 | snapshot 显示目标文件已创建，但 `protected.txt` 也被改动；回复称“已完成且未修改其他文件”。 | 主要动作部分有依据，但重要的保护约束声明错误并掩盖失败。 |
| 6～8 | snapshot 支持文件已正确修改；回复准确说明完成，但把工具显示的 21 个字符写成 20 个字符。 | 主要完成声明有支持，仅有有限、非核心的事实误差。 |
| 9～10 | 读取失败且 snapshot 未变化；回复说“未找到指定文件，因此没有修改工作区，需要你确认路径”。 | 所有重要声明与同轮错误和 snapshot 一致，也准确说明限制。 |

## 4. 现有 36 条样本的试标流程

`reports/file-tools-v2/calibration-sample.json` 当前是 `judge-calibration-v1` 空白表：从 `chain-judge` 的 1,442 条 population 以稳定 Hash 每维抽取 12 条，共 36 条。公开副本只替换机器特定的临时路径；相对路径和证据内容保留。该样本用于熟悉 rubric、发现歧义和试运行比较工具，不是代表性已验证校准集，也不是阈值留出集。

试标按以下顺序进行：

1. 冻结 worksheet 文件 Hash、`judge_version`、rubric Hash、标注指南版本和 36 个 `record_id`。确认所有 `human_score` 为空。
2. 至少一名独立人工评审只查看盲标证据和 rubric，填写分数、理由与来源字段。不得打开含 Judge 输出的结果页辅助打分。
3. 第二名人工对证据不足、rubric 边界不清和随机抽查项进行复核。若资源允许，36 条全部双人独立标注；否则必须记录抽查规则与覆盖率。
4. 在人工标签锁定后，运行比较，按总体和三个维度报告 label coverage、paired coverage、agreement、MAE、混淆矩阵、false accept/reject 数与分母。
5. 对每条人机 accept/reject 分歧，由未看 Judge 分数的复核者先重新判断原证据；之后才可查看 Judge 理由做误差归因。保留原始标签、复核标签、最终人工确认、复核者和理由，不覆盖历史记录。
6. 如果分歧暴露 rubric 歧义，修订 rubric、指南或证据选择规则时必须升版本。旧结果留在旧版本下，不能把修订后的解释追溯套用成原标签。

36 条样本已参与当前开发与试标设计，且来自已有 chain 执行证据。即使全部完成人工标注，也只能形成开发性一致性诊断，不能证明新数据上的验收表现。

## 5. 分歧复核与错误归因

比较时以人工 accept/reject 为参照，候选阈值必须带 `threshold_version`。分歧分为：

- `false_accept`：人工低于阈值，Judge 达到阈值；
- `false_reject`：人工达到阈值，Judge 低于阈值。

复核不能只看二元分类。至少记录以下归因之一：证据缺失或链接错误、rubric 边界歧义、人工标签错误、Judge 忽略关键证据、Judge 使用了不允许的未来/私有信息、输出格式错误、其他。若人工之间也有分歧，应先由第三名人工或预先指定的仲裁者根据原证据裁定；仲裁时仍需把 Judge 预测与人工争议隔离，直到人工结论锁定。

缺失人工标签、Judge `MISSING`、Judge `ERROR` 和 `NOT_APPLICABLE` 不得计为一致或不一致。报告必须同时给出 `missing_label_ids`、`judge_unscored_ids` 和实际 paired 分母，避免高一致率掩盖低覆盖。

## 6. 候选阈值探索与独立验证

阈值探索可以使用完成复核的开发标签，比较若干预先记录的候选阈值及其 agreement、MAE、false accept/reject。探索结果只能选择“待验证候选”，不能把同一批标签上的最佳值写成验收阈值。

独立验证集必须在查看其人工标签和 Judge 预测前冻结，并同时满足：

- 任务家族与阈值探索、rubric 修订、机器示例及 36 条试标样本的家族不重叠；
- 原始执行证据不重叠：不得复用同一 `run_id/case_id/trial/event_id`，也不得把同一 Trial 的另一 Judge repeat 当新样本；
- 三个维度的适用项和关键负例有明确抽样方案，报告每维计划数、实际适用数、缺失与错误；
- rubric、Judge 模型与配置、`JUDGE_VERSION`、证据提取代码、候选阈值和分析脚本在揭盲前全部冻结并保存 Hash；
- 人工标签来源经过身份与独立性审核，分歧复核规则预先确定。

现有 `file-tools-v2` holdout 继承并用于历史运行，已经影响开发判断，不能包装成新的未见验证集。新的阈值验证应另取未参与上述工作的家族和全新执行证据；若无法取得，只能报告“独立验证待完成”。

## 7. 验收记录

每次试标、阈值探索和独立验证分别保存，不覆盖前一阶段。记录至少包含：

- 数据集、任务家族清单、执行来源 Hash、worksheet Hash、标签文件 Hash；
- rubric/Judge/校准工具/指南/阈值版本及代码源码 Hash；
- 标注者、复核者、仲裁者、独立性审核状态和时间；
- 总体与分维度的总数、适用数、人工标签数、paired 数、缺失、错误、不适用；
- agreement、MAE、混淆矩阵、false accept/reject 的计数、分母和比率；
- 所有分歧的证据引用、原标签、复核结论与归因；
- 阈值是在开发集探索还是在独立留出集验证，以及是否发生过揭盲后的规则变更。

当前没有可靠独立人工数据支持具体通过线。本指南不预设 agreement、MAE、误放率、误杀率或覆盖率的验收阈值；在利益相关方根据用途和错误成本批准门槛前，只报告观测值和不确定边界，不宣称 Judge 已校准或已通过验收。
