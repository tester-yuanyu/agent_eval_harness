# Explicit configuration

The root CLI does not interpret executable bindings from a dataset. `configs/agents/external-static.json` is a trusted evaluator `RuntimeBinding` for the existing static external adapter. It accepts candidate intake with `eval-suite eval validate --input CANDIDATE_DIR --binding configs/agents/external-static.json` and `eval-suite eval run --input CANDIDATE_DIR --binding configs/agents/external-static.json --output-dir RUN_DIR`. A candidate must use the matching `mini_agent` identity and supported static operations. This binding does not invoke the reference Agent or a model.

For an external stdio Agent, create a trusted JSON binding using the evaluator's existing fields: `version: "1.0"`, `agent_id`, `adapter: "stdio"`, `argv`, optional absolute `python` and `agent_root`, and `env_names` (variable names only). With `python` set, `argv[0]` must be an absolute worker script path. Executable bindings are user-owned configuration, never synthesized from expected answers. See `eval-suite eval run --help` for accepted input modes; `--binding` belongs to candidate intake (`--input`), not legacy `--dataset` mode. No new HTTP/remote transport is implied.

`eval-suite agent sync --name NAME --repository REPOSITORY --ref REF` explicitly fetches a source and returns its full commit, tree, and detached checkout path. Use `eval-suite agent resolve --name NAME --commit FULL_COMMIT` to recheck it without network access. Resolution directly verifies tracked file bytes, symlink targets and executable bits against the commit tree, independently of Git index flags and cached file metadata. Submodules are not fetched; populated submodules require separate pinned verification. Bind to the resolved checkout explicitly; running evaluations never pulls code. The source index records Git provenance, not complete dependencies, environment identity, or an endpoint's deployed version.

The bundle index is `data/bundle-index.json`. `bundle list` discovers publications; `bundle resolve --agent mini_agent --version 0.1.0` validates the fixed publication before returning a path and both protocol Hashes. No implicit newest version or mutable alias exists. Publication version and the Agent's declared `agent_version` are separate fields.

For comparisons, the reference dataset, reference capability contracts and controlled configuration must stay fixed. The current runtime capabilities may change when allowed by existing compatibility rules. In legacy mode, `--capability-bundle` supplies the reference bundle and must still match the frozen dataset Hash; it is not a new runtime identity selector. Runtime selection belongs to the installed Provider or explicit trusted binding. `eval-suite eval compare --baseline-run BASELINE_RUN_DIR --candidate CANDIDATE_RUN_DIR --output-dir COMPARISON_DIR` forwards to the evaluator's existing comparison checks. `--baseline-run` is a compare-only spelling of `--baseline`, not a run option or an automatic baseline lookup.
